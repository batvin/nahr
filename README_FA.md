# نهر (Nahr)

تونل رمزنگاریشدهٔ چندترنسپورته با **پنل وب** و **بخش محک** داخلی. این پروژه شبیه کاری است که در [Kariz](https://github.com/Erfan-XRay/Kariz) دیدید (سرورها، تانلها، نقشه، گزارشات، تست سرعت)، ولی **از صفر نوشته شده** و هیچ کدی از آن ریپو کپی نشده است. دلیلش هم مشخص است: مجوز کاریز «source-available» است و کپی/استفاده از core آن در جای دیگر مجاز نیست.

> نتیجٔ تحقیقم در پایین است؛ خلاصهاش: **برای مسیر معمولی `tcpmux` بهترینه**، روی مسیر پراتلاف `udp` (KCPمانند) برنده میشود، و وقتی UDP بسته است `wss`. به همین دلیل من هر پنج ترنسپورت را ساختم تا «محک» خودتان روی مسیرتان تعیین کند کدام بهتر است.

---

## آنچه وجود دارد

- **پنج ترنسپورت:** `tcp`، `tcpmux`، `ws`، `wss`، `udp` (UDP مهرومومشده + ARQ با ACK تجمعی و رمزنگاری هر بسته).
- **رمزنگاری:** X25519 forward-secret + HKDF-SHA256 + AES-256-GCM；احراز هویت متقابل با توکن (HMAC).
- **مالتیپلکسر:** جریانهای کاربر روی یک یا چند اتصال پایدار، با backpressure و DATAGRAM جداگانه برای UDP.
- **پروکسی SOCKS5:** CONNECT (TCP) و UDP ASSOCIATE — مناسب مرورگر، DNS و بازی.
- **پنل وب:** نمای کلی + نقشه زنده، سرورها، تانلها، محک، گزارشات زنده (SSE)، تنظیمات، تم تاریک/روشن، RTL کامل.
- **محک:** کاوش ۱۰ حالت (۵ ترنسپورت × ۲ جهت)، سپس تست سرعت سه گزینهٔ برتر، امتیازدهی وزندار و «اعمال بهترین» با یک کلیک.
- **دمو محلی:** دو ایجنت + پنج تانل آماده بدون نیاز به سرور یا کامپایلر.
- **وبسایت و مستندات:** صفحهٔ فرود و مستندات فارسی در همان سرور پنل.

---

## کدام ترنسپورت خوب است؟ (تحقیق)

| شرایط مسیر | بهترین | دلیل |
|---|---|---|
| مسیر تمیز، Interior/فاصله کم | **`tcpmux`** | چند اتصال پایدار، بدون handshake مکرر، کمترین سربار — پیشفرض نهر |
| فاصله زیاد، اتلاف ۱٪+، اینترنشنال | **`udp`** | TCP با هر اتلاف نرخش را نصف میکند؛ ARQ با retransmission سریعتر بازیابی میکند |
| UDP مسدود یا throttle میشود | **`wss`** | شبیه HTTPS دیده میشود و از CDN/پروکسی معکوس عبور میکند |
| پشت CDN | **`ws` / `wss`** | تنها HTTP قابل عبور است |
| بازی و صوت روی UDP سالم | **`udp`** + پروفایل gaming | تأخیر پایدارتر از throughput خام |
| نمیدانید چه عبور میکند | **اجرای محک** | ۱۰ حالت را واقعاً امتحان میکند |

**توصیهٔ من:** پیشفرض `tcpmux` بماند؛ اگر محک اختلاف قابلتوجهی نشان داد، همان گزینهای را که بالاترین امتیاز دارد اعمال کنید. امتیاز محک وزنهای پیشفرض `speed 50% / latency 30% / stability 20%` دارد؛ پروفایل gaming وزن تأخیر و پایداری را بالا میبرد.

## اجرا (ویندوز / لینوکس / مک)

### نصب تکخطی روی سرور (پیشنهادی)

اگر فقط میخواهید روی سرور Ubuntu/Debian نصب کنید و آدرس پنل را بگیرید، یک خط کافی است:

```bash
curl -fsSL https://raw.githubusercontent.com/batvin/nahr/main/scripts/quick-install.sh | sudo bash
```

اسکریپت بهطور خودکار:

- Node.js 22 را نصب میکند (اگر نباشد)،
- پروژه را در `/opt/nahr` میگیرند،
- وابستگیها را نصب میکند،
- توکن مشترک میسازد،
- دو سرویس `nahr-panel` (فقط `127.0.0.1:18080`) و `nahr-agent` (`0.0.0.0:7700`) راهاندازی میکند،
- در آخر آدرس پنل، توکن و دستور SSH tunnel را چاپ میکند.

سپس از کامپیوتر خود:

```bash
ssh -L 18080:127.0.0.1:18080 root@<SERVER_IP>
```

و در مرورگر: <http://localhost:18080/panel>

### اتصال سرور دوم با یک کد (پیشنهادی برای دو سرور)

وقتی نهر روی سرور اول نصب شد، نیازی به نصب پنل روی سرور دوم نیست. روی سرور پنل کد اتصال بسازید:

```bash
sudo nahr-manager                       # گزینهٔ 10: ساخت کد اتصال تکخطی
# یا مستقیم:
nahr connect-code --agent http://PANEL_SERVER_IP:7700 --name outside --ttl 24
```

کد `nh1_...` (و دستور کامل) چاپ میشود. آن دستور را روی سرور دوم با root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/batvin/nahr/main/scripts/quick-install.sh) --agent nh1_...
```

اسکریپت ابتدا نهر و فرمانهای `nahr` / `nahr-manager` را نصب میکند، سپس توکن و شناسه را از کد میخواند و سرور را از طریق ایجنت سرور پنل به پنل اضافه میکند. در پایان فقط `nahr-agent` روی سرور دوم فعال است و پنل لوکال باقی میماند.

نکات:

- اگر سرور از قبل به پنلی وصل باشد، اسکریپت پیش از جایگزینی میپرسد؛ با `--replace` میشود بدون سؤال جایگزین کرد.
- کد حاوی توکن مشترک است و بهطور پیشفرض ۲۴ ساعت اعتبار دارد؛ آن را محرمانه نگه دارید.
- همان کد را از پنل هم میشود ساخت: تب **تنظیمات** → «اتصال سرور جدید با یک کد»، یا تب **سرورها** → «ساخت کد اتصال تکخطی».
- در تب **سرورها** میشود کد `nh1_` را هم مستقیم چسباند و همراه با آدرس سرور ثبت کرد — نیازی به ترمینال روی سرور دوم نیست. فهرست سرورها بهطور خودکار تازه میشود و سرور متصلشده بدون رفرش صفحه دیده میشود.
- از نسخهٔ ۰٫۲٫۱، اعتبارسنجی کد توسط خود پنل انجام میشود؛ حتی اگر توکن سرویس ایجنت پنل قدیمی باشد، اتصال با کد معتبر کار میکند.

### منوی ترمینالی (پس از نصب تکخطی)

اسکریپت نصب، دو فرمان `nahr` و `nahr-manager` را هم در `/usr/local/bin` نصب میکند. برای دیدن منو:

```bash
sudo nahr-manager
```

منو کاملاً فارسی و RTL است و با ↑/↓ حرکت میکند؛ با زدن شمارهٔ گزینه هم مستقیم به همان گزینه میروید. گزینهها:

| گزینه | کار |
|---|---|
| نصب یا بهروزرسانی نهر | آخرین نسخهٔ `main` را از گیت هاب میگیرد و سرویسها را دوباره راهاندازی میکند |
| وضعیت و آدرسها | میزبان، IPv4/IPv6، پورتها، تانلهای زنده، وضعیت سرویسها و توکن پوشاندهشده |
| نصب پنل وب / حذف پنل وب | فعال یا غیرفعال کردن `nahr-panel` (فایتها باقی میمانند) |
| لینک ورود به پنل | آدرس `127.0.0.1:18080/panel` و دستور `ssh -L` مربوط به IP سرور |
| رمز ورود / توکن مشترک | نمایش کامل توکن موجود در `state.json` |
| آدرسها و گواهیها | لیست IPها و گواهیهای self-signed ایجنت |
| پورت پنل | تغییر پورت `--port` در واحد systemd و ریاستارت سرویس |
| اتصال ایجنت به پنل | اضافه کردن این سرور به پنل دیگری با `POST /api/servers` |
| ساخت کد اتصال تکخطی | ساخت کد `nh1_` و دستور نصب/اتصال تکخطی برای سرور خارج |
| حذف ایجنت | متوقف و غیرفعال کردن `nahr-agent` |
| لاگ زنده | `journalctl -u nahr-panel -u nahr-agent -f` |
| حذف کامل نهر | پاک کردن سرویسها، `/opt/nahr`، `/var/lib/nahr` و فرمان manager (پس از تایپ «بله») |

برای خروج `q` یا `Ctrl+C` را بزنید. منو از هیچ وابستگی خارجی استفاده نمیکند و فقط از کتابخانهٔ استاندارد Node و ANSI بهره میبرد.

### وبسایت موشن و گرافیک

صفحهٔ فرود (`/`) و مستندات (`/docs`) دارای جلوههای موشن، تونل سهبعدی با CSS، ذرات متحرک، نمودار جریان پویا، نوار امتیاز محک، تیلت سهبعدی کارتها و منوی ترمینالی شبیهسازی شدهاند و بخشی هم جریان «دو سرور، یک کد، یک دستور» را نشان میدهد. همه با CSS و JavaScript سادهاند؛ نه Three.js و نه مرحلهٔ build، تا روی سرور ۱ گیگابایتی هم سبک بمانند.

### نصب دستی

نیاز: **Node.js 20+** و npm. کامپایلر لازم نیست.

اگر میخواهید از گیت هاب نصب کنید:

```bash
git clone https://github.com/batvin/nahr.git
cd nahr
npm install
npm test
```

سپس برای دموی محلی:

```bash
npm run demo
```

سپس باز کنید: <http://localhost:8080/panel>

دمو دو ایجنت محلی و ۵ تانل (`tcpmux`, `tcp`, `ws`, `wss`, `udp`) میسازد و تانل `tcpmux` را راهاندازی میکند. وارد تب **محک** شوید، دو سرور دمو انتخاباند و دکمهٔ «شروع محک» را بزنید. حدود ۳۰–۵۰ ثانیه بعد رتبهبندی کامل نمایش داده میشود.

دستورات دیگر:

```bash
npm start                # فقط پنل + وبسایت + مستندات (پورت 8080)
node bin/nahr.js panel --port 9000
node bin/nahr.js agent --port 7700 --id s1 --host 0.0.0.0
node bin/nahr.js bench --seconds 3 --profile balanced
PORT=8081 npm run demo
```

## اتصال سرور واقعی (گام به گام)

برای حالت سریع، از روش «اتصال سرور دوم با یک کد» در بالا استفاده کنید. در ادامه مسیر دستی توضیح داده میشود.

فرض کنید دو سرور دارید:

- **سرور ورودی** ( روی آن کاربرها به SOCKS5 وصل میشوند): `1.1.1.1`
- **سرور خروجی** (ترافیک از آن خارج میشود): `2.2.2.2`
- پنل روی یک کامپیوتر/سرور سوم (یا همان سرور ورودی) اجرا میشود.

### گام ۱ — نصب Node و کپی پروژه روی **هر دو** سرور

```bash
# لینوکس (Ubuntu/Debian)
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs git
git clone <آدرس-مخزن-شما> nahr
cd nahr
npm install --omit=dev
```

### گام ۲ — گرفتن کلید مشترک از پنل

پنل را اجرا کنید (`npm start`) و بروید به <http://localhost:8080/panel> → تب **تنظیمات** → «کلید مشترک». همین کلید را باید روی هر دو ایجنت تنظیم کنید.

### گام ۳ — اجرای ایجنت روی هر سرور

روی سرور ورودی:

```bash
cd nahr
node bin/nahr.js agent --port 7700 --id server-in --name "ورودی" --host 0.0.0.0 \
  --token <کلید-مشترک>
```

روی سرور خروجی:

```bash
cd nahr
node bin/nahr.js agent --port 7700 --id server-out --name "خروجی" --host 0.0.0.0 \
  --token <کلید-مشترک>
```

برای سرویس دائیم:

```bash
# فایل سرویس را ویرایش و NAHR_TOKEN و مسیرها را درست کنید
sudo nano scripts/nahr-agent.service
sudo cp scripts/nahr-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nahr-agent
sudo journalctl -u nahr-agent -f
```

### گام ۴ — باز کردن پورت ۷۷۰۰ در فایروال هر دو سرور

```bash
sudo ufw allow 7700/tcp
```

پورت ۷۷۰۰ فقط برای ارتباط پنل با ایجنت است. اگر پنل و ایجنت روی یک سرورند، نیازی به بازکردن عمومی آن نیست — از `127.0.0.1` استفاده کنید.

### گام ۵ — معرفی سرورها به پنل

تب **سرورها** → «افزودن سرور»، برای هر سرور:

| فیلد | سرور ورودی | سرور خروجی |
|---|---|---|
| نام | ورودی | خروجی |
| آدرس | `1.1.1.1` | `2.2.2.2` |
| پورت ایجنت | `7700` | `7700` |
| توکن | همان کلید مشترک | همان کلید مشترک |

پس از ذخیره، badge «آنلاین» را بررسی کنید.

### گام ۶ — ساخت و راهاندازی تانل

تب **تانلها** → «تانل جدید»:

- ورودی: `ورودی`، خروجی: `خروجی`
- ترنسپورت: `TCP MUX` (پیشفرض)
- حالت: **مستقیم** (اگر سرور خروجی IP عمومی ندارد، **معکوس** را انتخاب کنید)

سه نوع پورت کاملاً جداگانه وجود دارد — اشتباه نگیرید:

| فیلد در پنل | کارش | کجا شنیده میشود |
|---|---|---|
| **پورت ارتباطی بین دو سرور** (`listenPort`) | فقط ارتباط رمزنگاریشدهٔ نهر بین ورودی و خروجی | سروری که در حالت مستقیم «خروجی» و در حالت معکوس «ورودی» است |
| **پورت SOCKS5 محلی** (`socksPort`) | پروکسیعمومی برای هر مقصد دلخواه | سرور ورودی |
| **پورت فوروارد** (`forwards`) | تانل کردن یک پورت مشخص به یک مقصد ثابت | سرور ورودی |

سپس دکمهٔ «راه اندازی» را بزنید.

### گام ۶٫۱ — تانل کردن پورت دلخواه (مثلاً V2Ray)

اگر میخواهید کاربر به جای پروکسی SOCKS، صرفاً به یک پورت مشخص وصل شود (مثلاً پورت ۱۰۰۰۰ سرویس V2Ray روی سرور خروجی)، در همان فرم تانل، قسمت **«پورتهایی که تانل میشوند»** را پر کنید. هر خط به این شکل است:

```
<پورت محلی>  <آدرس مقصد>:<پورت مقصد>
```

مثال:

```
1081 127.0.0.1:10000
8443 127.0.0.1:8443
```

یعنی:

- اتصال به `ورودی:1081` → از تونل رد میشود → به `خروجی:127.0.0.1:10000` میرسد.
- اتصال به `ورودی:8443` → به `خروجی:127.0.0.1:8443` میرسد.

آدرس مقصد میتواند IP دیگری هم باشد (مثلاً `10.0.0.5:3306`)؛ این آدرس از دید **سرور خروجی** تفسیر میشود. برای باز کردن پورت فوروارد روی تمام رابطها، به جای `1081` بنویسید `0.0.0.0:1081`.

توجه: پورت فوروارد با پورت ارتباطی بین دو سرور فرق دارد. مثلاً میشود پورت ارتباطی `7701` باشد و پورت فوروارد `1081` — پس وقتی کلاینت به `ورودی:1081` وصل میشود، ترافیک داخل تونل روی پورت `7701` بین دو سرور جابجا میشود.

اگر فیلد فوروارد خالی بماند، تانل فقط همان رفتار قدیمی SOCKS5 را دارد.

### گام ۷ — اتصال کاربرها

در مرورگر یا نرمافزار موردنظر، پروکسی SOCKS5 را روی آدرس سرور ورودی تنظیم کنید:

```
SOCKS5 host: 1.1.1.1
SOCKS5 port: <socksPort مثلاً 1080>
```

پورت `socksPort` روی **سرور ورودی** است (در حالت معکوس هم همانجا شنیده میشود).

### گام ۸ — اجرای محک و اعمال بهترین ترنسپورت

تب **محک** → دو سرور را انتخاب کنید → «شروع محک». بعد از ۳۰–۵۰ ثانیه رتبهبندی ۱۰ حالت نمایش داده میشود؛ دکمهٔ «اعمال بهترین» ترنسپورت برنده را روی تانل تنظیم میکند.

## ساختار کد

```
bin/nahr.js          CLI: panel / agent / demo / bench
bin/nahr-manager.js  منوی تعاملی ترمینالی (فارسی، RTL)
src/manager.js       تشخیص وضعیت، سرویسها و عملیات منو
src/connect.js       کد nh1_، ثبت سرور و دستور اتصال تکخطی
src/secure.js        X25519, HKDF, AES-GCM stream + datagram sealing
src/mux.js           multiplexer جریانها و DATAGRAM
src/transports.js    tcp / tcpmux / ws / wss / udp
src/socks5.js        SOCKS5 CONNECT + UDP ASSOCIATE
src/tunnel.js        منطق ورودی/خروجی و اتصال مجدد
src/benchproto.js    پروتکل ping/download/upload بین ایجنتها
src/bench.js         موتور محک پنل و امتیازدهی
src/agent.js         سرویس کنترلی HTTP روی هر سرور
src/panel.js         پنل، API، دمو، فایلهای استاتیک
web/                 رابط پنل + وبسایت موشن/سهبعدی + مستندات
data/                state.json، لاگ و گواهی self-signed (خودکار ساخته میشود)
```

## محدودیتهای نسخهٔ ۰٫۱

- احراز هویت پنل و ایجنتها فعلاً فقط توکن مشترک است (بدون حساب کاربری)، بنابراین پنل را پشت TLS/Reverse proxy یا فقط روی localhost بگذارید.
- هشدار Telegram، شبکههای خصوصی GRE/VXLAN، سهمیه Monthly و نصب self-update از مواردی هستند که در کاریز هست و در این نسخهٔ نهر نیامدهاند.
- ترنسپورت UDP با KCP **سازگاری سیمی ندارد**؛ نهر تنها از الگوی آن الهام گرفته است.
- محک ترافیک واقعی مصرف میکند و نتایجش وابسته به لحظهاند؛ چند بار اجرا کنید.
